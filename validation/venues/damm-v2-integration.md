# DAMM v2 keyless SDK adapter

The cached token/WSOL adapter in `src/venues/damm_v2.rs` ports bounded pure mathematics from Meteora's MIT TypeScript SDK 1.4.10 at exact commit [`37cd9e690d7b5fb6182638a21b86e0e1bf636a7e`](https://github.com/MeteoraAg/cp-amm-sdk/tree/37cd9e690d7b5fb6182638a21b86e0e1bf636a7e). It does not introduce a JavaScript runtime dependency or give a provider, SDK client, constructor, middleware or simulation signing keys. Custody, signing and submission remain caller-owned. Unsigned ATA/WSOL setup is part of the shared keyless SDK builder.

The pinned codeload archive was fetched on 2026-09-25 and all 87 regular files matched the reviewed local source byte-for-byte. [The source manifest](damm-v2-source-manifest.json) records the archive SHA-256 and every consulted file hash. [The original MIT notice](licenses/meteora-cp-amm-sdk-MIT.txt) is preserved. No source from Meteora's separately licensed Rust DAMM v2 program was read or copied.

## Supported state and quotes

Execution supports exact-input swaps in either token/WSOL orientation, including legacy SPL Token and the parent adapter's narrowly permitted Token-2022 metadata/immutable-owner extensions. Transfer fees, hooks and other unsupported extensions are rejected. Concentrated pools support collection in the output token (mode 0) or only token B (mode 1), with layout versions 0 and 1. Compounding pools (collection mode 2) require layout version 1, tracked positive A/B reserves, full-range bounds, and the exact tracked-reserve square-root price. Concentrated quotes use liquidity and Q64.64 square-root price, including the protocol's asymmetric rounding and range-exhaustion rejection. Compounding quotes use tracked constant-product reserves. Neither path accepts partial fills or exact-output orders.

Base fee modes 0/1 implement static and time-based linear/exponential schedules; modes 3/4 implement price-based linear/exponential schedules with expiry. Mode 2 implements existing token-B-only rate limiters with the exact included-input piecewise fee formula and both upward rounding steps. It is applied only to B-to-A swaps through its inclusive expiry point. Such instructions include the Instructions sysvar as the sole remaining account. Fee versions 0 and 1 use their corresponding 50%/99% caps. Minimum output is integer output after fees, reduced by the user's requested slippage. Fees are charged on input only for B-to-A token-B-only/compounding pools; otherwise they are charged on output. Indicative displayed fees use one raw input unit and do not represent the size-dependent limiter fee of every order.

## Authentication and decoding

Pool ownership, the exact 1112-byte layout, and the Anchor pool discriminator are checked before reading fields. Authenticated A/B mint identities are at offsets 168/200. Mutable dependencies are the pool, both mints, both vaults and Clock. Pool state, mint program flags, mint initialization, token vault mint/authority/state, native WSOL mode, canonical `token_vault` PDAs (`mint`, then `pool`), protocol fee coverage, vault balances and input overflow are checked. Delegated/externally closable vaults are rejected. The authority derives from `pool_authority`; event authority derives from `__event_authority`.

The pool account does not retain the config key used for configuration-derived pool addresses. The adapter therefore authenticates a pool using owner/layout and its canonical vault relationships; it does not invent a config address or claim a pool-address rederivation that the stored account cannot support. `pool_type` is restricted to zero; the MIT SDK lacks a documented enum that would establish other values. Former partner and reserve padding fields may retain historical data, as explicitly documented by the IDL. Future-reserved bytes are required to remain zero. Initialized farming/reward state is currently excluded rather than claiming support for unreviewed reward accrual.

Clock is validated as the 40-byte sysvar owned by the sysvar program. Activation uses its slot or nonnegative timestamp according to the pool flag. Early whitelisted-vault trading is not supported: ordinary execution always waits for activation. The parent coherent-cache freshness contract applies to these dependencies. Spot price is the exact square of the cached Q64.64 sqrt price, inverted when needed for SOL/token orientation, with decimal scaling left to the parent display layer.

## Explicit dynamic-fee limitation

Dynamic-fee-enabled pool layouts are recognized, but resolution and executable snapshots are rejected with `DAMM v2 dynamic fee refresh is unsupported`. The pinned SDK's `getTotalFeeNumerator` reads the stored `volatilityAccumulator` directly, and its quote path contains no pre-swap Clock-dependent reference/accumulator refresh. Agreement with that SDK's cached value would not prove agreement with the next on-chain swap. This adapter therefore neither reuses a stale accumulator nor silently substitutes a maximum fee that widens the user's economic tolerance. Disabled dynamic-fee state must be entirely empty. Implementing dynamic fees requires an additional permissively sourced and independently verified refresh algorithm.
